# PQT_labnet

The PQT lab's copy of [LabNet](https://github.com/mill0851/labnet). LabNet has five parts:
- Central: users, API keys, the device directory and leases.
- The Lab PC runtime, which serves instruments over gRPC.
- The client library that experiment scripts use.
- The web Control Center.
- The Automation runner.

On 2026-10-27, `main` matched upstream `main` exactly (`cda6c9f`, release 3.0.0).
The lab's own configuration is in `sites/pqt/`.

## Structure
- `packages/labnet/`: the core: Central, the Lab PC runtime (`lab_pc/`), the client, `devices/core` (facades,
  `BaseDeviceInterface`, `site_limits`), `contracts/registry.py`, driver tooling (`driver/`), `release/`, `testing/`.
- `packages/labnet-control-center/`: the web UI and the safe-state watchdog.
- `packages/labnet-automation/`: the Automation runner (`labnet-runner`).
- `packages/labnet-sim/`: the simulated instruments. It is also the reference driver package; `simulated_wavemeter/` is a good one to copy.
- `sites/pqt/`: the PQT config.
  - Env templates, `Caddyfile.example` and `inventories/lab_pc_01.py`.
  - `labnet bundle` packs it; `labnet update` installs it to `C:\ProgramData\LabNet\site\`.
- `drivers/pqt_drivers/` (*planned*): the LabNet driver package that wraps `PQT_devices`. The sync writes it, not people.
  Create it once with `labnet driver new pqt-drivers --service <Family> --directory drivers/pqt_drivers`.
- `docs/`: the full documentation. Start with `concepts.md`, `drivers.md`, `clients.md` and `deploying/`.
- `examples/`: client scripts 01-05, tested by `tests/examples/`.

## Commands (PowerShell, in `PQT_labnet` with the workspace `.venv` active)
CONTRIBUTING.md lists the CI checks as `uv run ...`. uv is not installed here, so run them directly:
```powershell
python -m pytest
lint-imports
labnet driver build --core --check --import-check
labnet driver build --check --project packages/labnet-sim
python .github/scripts/no_site_names.py
```
The full `pytest` run takes about 4 minutes.
- `labnet dev up` / `labnet dev down` starts and stops a whole simulated lab on 127.0.0.1. Its state lives in `.devnet\`.
- After any dependency change, regenerate `uv.lock` with `uv lock`, because CI runs `uv sync --locked`.

## Drivers, inventories and limits
- **Drivers.** A LabNet driver is its own package. CONTRIBUTING.md keeps them out of `packages/`; this lab keeps its one in `drivers/pqt_drivers/`. It has:
  - a `.proto` file;
  - a `Physical<Name>(BaseDeviceInterface)` class;
  - code generated by `labnet driver build`;
  - `labnet.devices` entry points.

  Start a new one with `labnet driver new <name> --service <Name>`. The full guide is `docs/drivers.md`.
- **Inventories.** Each Lab PC serves the objects that `create_devices()` returns in `sites/pqt/inventories/lab_pc_XX.py`.
  - Its `lab-pc.env` selects the file with `LABNET_DEVICE_INVENTORY`.
  - A `device_id` must be unique across the whole network and must never change.
- **Site limits.** Wrap automatable instruments in `site_limits(dev, limits=..., choices=...)` from `labnet.devices.core`.
  - Site limits can only narrow a driver's limits.
  - `lab_pc_01.py` has a commented-out example.
- **Current state.** Only simulated devices for now: `lab_pc_01.py` returns one `PhysicalSimulatedWavemeter`.
  Real instruments will come only through the PQT_devices sync. Don't add other real-device drivers, and don't
  uncomment the old `PhysicalSacherLaser` example in `lab_pc_01.py`.

## Deployment
Runtime PCs never run from git. A maintainer builds a bundle, and each PC installs it:
```powershell
labnet bundle --site sites/pqt --driver <driver package dir> --driver packages/labnet-sim
labnet update --from dist\labnet-<version>-pqt --role lab-pc    # or central | control-center | client
```
- Any `--driver` replaces the default `packages/labnet-sim`, but `lab_pc_01.py` still imports `labnet_sim`, so pass it explicitly.
- *Planned* PQT drivers: add `--driver drivers/pqt_drivers --driver ..\PQT_devices`. `pqt-devices` isn't on PyPI; the
  bundle carries its wheel, built from the working tree, so check out the commit the sync PR names first.
- Install in this order: Central -> Control Center -> each Lab PC -> clients. Stop processes in reverse order (`docs/deploying/updating.md`).
- Each role keeps its last three environments for rollback.

## Cross-repo impact
- PQT_projects scripts use this repo's client (`LabClient`, device facades), so a contract change can break them.
- *Planned sync:* after each PQT_devices push, the `sync-labnet-from-devices` skill (on the pusher's PC) updates
  `drivers/pqt_drivers/`: the protos, pass-through methods, tests and the exact `pqt-devices==X.Y.Z` pin. It runs
  `labnet driver build` and the tests, and pushes a branch `sync/pqt-devices-<version>`. The PR names the synced
  PQT_devices commit.
- A maintainer reviews the PR and adds any `sites/pqt/inventories/` entries before a bundle is built. A removed
  or renamed PQT_devices method keeps its old RPC and is flagged in the PR.

## Upstream (github.com/mill0851/labnet)
Change LabNet itself (`packages/`, `docs/`, `examples/`, `tests/`) only upstream. Here, change only `sites/pqt/` and
`drivers/`, so merging an upstream release never conflicts. To take a release:
```powershell
git remote add upstream https://github.com/mill0851/labnet.git    # once
git fetch upstream --tags
git switch -c labnet-<version>
git merge v<version>            # then read CHANGELOG.md for breaking changes
```
Run the checks under Commands, plus `labnet driver build --check --project drivers/pqt_drivers`; if it reports
stale code, run it without `--check`. Then open a PR to `main`. Never push upstream's `v*` tags to origin:
`release.yml` starts a release on any `v*` tag.

## Rules
- Never weaken a safety check: leases, limits, site limits, approvals, grants, or TLS off loopback. CONTRIBUTING requires a discussion first.
- Never hand-edit `_generated/` or `grpc/generated/`. Edit the `.proto`, then run `labnet driver build`.
- Keep deployed `.proto` contracts backward compatible: never renumber or retype a field, add new fields as optional, and reserve removed numbers.
- Keep lab names, IPs and instruments out of `packages/`, `examples/` and `tests/`. `no_site_names.py` enforces this.
- Never commit `.env` files, API keys, certificates or private keys. The real ones live only in `C:\ProgramData\LabNet\` on each PC.
- Never run `labnet update`, start or stop `labnet-lab-pc`, or push a `v*` tag unless the user explicitly asks. These affect running experiments and releases.
- Every change comes with tests. Also update the matching `docs/` page and add a `CHANGELOG.md` line under "unreleased".
